<Scene id="en-s1" label="Part 1/4" title="Who runs what: self-managed servers, managed services and serverless">

<p class="scene-intro">With servers of its own, a company handles everything from power to software patches; on AWS, the higher-level the service you choose, the more of the operating work AWS takes over.</p>

AWS calls this split the **shared responsibility model**: AWS is responsible for the cloud infrastructure, and the customer for what they put on it. Pick each way of running the order database and watch the tasks move to AWS.

<ResponsibilitySim client:visible />

<Takeaway>Managed service: AWS runs the infrastructure and the underlying software; you configure and use it. Serverless: there is no server to manage, and the service scales and bills for actual usage. Code and data are always your responsibility.</Takeaway>

</Scene>

<Scene id="en-s2" label="Part 2/4" title="One order's journey through AWS services">

<p class="scene-intro">A simple customer action passes through several services, each doing one job; knowing this path explains why the study path is split into networking, compute, database and integration layers.</p>

The simulation plays through eight steps on its own; pause it to go step by step. Each step links to the lesson about that service.

<OrderJourney client:visible />

<Takeaway>Networking (Route 53, CloudFront) brings the request in, compute (load balancer, EC2, Lambda) processes it, the database (RDS) stores the data, and integration (SQS) separates the steps so parts of the system do not wait on each other.</Takeaway>

</Scene>

<Scene id="en-s3" label="Part 3/4" title="Six groups of services and the study path's layers">

<p class="scene-intro">AWS offers more than two hundred services, but most belong to a few functional groups; knowing a service's group is the first step to knowing what problem it solves.</p>

The study path follows these groups: Layer 1 Networking, Layer 2 Security & Identity, Layer 3 Compute, Layer 4 Storage, Layer 5 Database and Layer 6 Integration, Monitoring & Operations. Sort the twelve services below into their groups.

<GroupSort client:visible />

<Takeaway>When you meet a new service, find its group first: networking, security, compute, storage, database, or integration and operations. The group tells you which kind of problem the service solves.</Takeaway>

</Scene>
