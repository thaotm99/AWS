<Scene id="en-s1" label="Part 1/6" title="Access from the internet: the control layers along the packet's path" questions={["exam5_q63", "exam4_q38", "exam3_q9", "exam3_q25", "exam6_q8"]}>

A subnet is a **public subnet** only when its route table has a `0.0.0.0/0` route to an **internet gateway (IGW)**. A request from the internet to ShopViet's web server passes in turn through the IGW, the **network ACL** at the subnet boundary, and the **security group** attached to the instance. Turn each condition on or off and send a request to find the control layer that is blocking traffic.

<PacketPath client:visible />

<Takeaway>Conditions for internet connectivity: a route to the IGW, a public IP (the IGW performs NAT between the public IP and the private IP), a NACL that allows both directions, and a security group that allows the inbound direction. Security groups are stateful: responses are allowed automatically. NACLs are stateless: the return direction must be allowed explicitly.</Takeaway>

</Scene>

<Scene id="en-s2" label="Part 2/6" title="Security group chain: ALB → EC2 → RDS" questions={["exam2_q28", "exam2_q55", "exam4_q52", "exam4_q26", "exam5_q29"]}>

ShopViet's web application has three tiers: an ALB receives user requests, EC2 runs the application, and RDS stores the data. Each tier should allow traffic only from the tier in front of it. Choose the inbound rules for EC2 and RDS, run the simulation, and watch both legitimate user requests and direct access attempts from outside.

<SgChain client:visible />

<Takeaway>Only the outermost tier (the ALB) allows traffic from the internet. Each tier behind it accepts traffic only from the security group of the tier in front of it. When a rule is missing: the ALB marks the target as unhealthy or the application gets a "connection timed out" error.</Takeaway>

</Scene>

<Scene id="en-s3" label="Part 3/6" title="NAT gateway: internet access for private subnets" questions={["exam3_q44", "exam3_q62", "exam6_q13", "exam3_q12"]}>

ShopViet's database and workers are in **private subnets** without public IPs, but they still need to download patches. A **NAT gateway** allows outbound connections but does not allow the internet to initiate inbound connections. Try three placements, then trigger a failure in AZ a.

<NatHaSim client:visible />

<Takeaway>A NAT gateway is a managed service for IPv4 traffic (and IPv6 through DNS64 and NAT64). A public NAT gateway in zonal mode is placed in a public subnet and belongs to one AZ; to tolerate an AZ failure: one NAT gateway per AZ and a route table that points to the NAT gateway in the same AZ. A regional NAT gateway automatically expands to the AZs that have workloads and does not need a public subnet.</Takeaway>

</Scene>

  { need: "Create a new account for each team to a common standard, using a shared network", answer: "Control Tower + shared VPC (RAM)",

<Takeaway>A small number of VPCs: VPC peering (low cost, but no transitive routing). Many VPCs, or on-premises connectivity as well: Transit Gateway. Many accounts in the same organization: VPC sharing.</Takeaway>

<Scene id="en-s6" label="Part 6/6" title="Connecting on premises: Site-to-Site VPN and Direct Connect" questions={["exam3_q18", "exam5_q10", "exam5_q41", "exam6_q25", "exam1_q37", "exam4_q48", "exam4_q7", "exam6_q45", "exam6_q34", "exam4_q18"]}>

ShopViet's office needs to connect to the VPC. There are two methods: **Site-to-Site VPN** travels over the internet with encryption, and **Direct Connect** is a dedicated connection to AWS. Each scenario below corresponds to a real requirement of the office. Choose a connection method and send a request to watch the traffic's path.

<HybridLinkSim client:visible />

<Takeaway>Fast to deploy, low cost: Site-to-Site VPN. A stable, dedicated connection: Direct Connect (set up a VPN on top when encryption is needed, and add a VPN as a backup connection). Multiple Regions: Direct Connect gateway. Accessing S3 over Direct Connect: public VIF. Branch offices communicating with each other: VPN CloudHub. Insufficient VPN throughput: Transit Gateway with ECMP.</Takeaway>

</Scene>

<Scene id="en-confuse" label="Common mistakes" title="Six configurations that look valid but do not work as expected" questions={["exam2_q20", "exam6_q63", "exam3_q44", "exam3_q21", "exam3_q65", "exam6_q59", "exam3_q12"]}>

The configurations below look reasonable in the console, but they behave differently in practice. Choose a scenario, try the option that is commonly applied first, then switch to the correct option.

<VpcMythsSim client:visible />

<Takeaway>A private hosted zone requires both enableDnsHostnames and enableDnsSupport. Outbound IPv4 traffic: NAT gateway (an egress-only IGW is for IPv6 only). Port forwarding or a bastion is required: NAT instance. A VPC with dedicated tenancy makes every instance run as dedicated. The source of a security group rule cannot be an internet gateway. Two EC2 instances should communicate over private IPs: access over a public IP incurs data transfer charges; over private IPs, traffic between two AZs is still charged per GB.</Takeaway>

</Scene>
