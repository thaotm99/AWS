<Takeaway>Baseline load running 24/7: Reserved Instances or Savings Plans. Interruption-tolerant tasks: Spot (a persistent request or Spot Fleet to keep processing). Variable load that cannot tolerate interruption: On-Demand. Single-tenant hardware, with no need to control the host and no per-socket or per-core licenses: Dedicated Instances (billed per instance); per-socket or per-core licenses: Dedicated Hosts (billed per host). A discount that covers EC2, Fargate and Lambda: Compute Savings Plan.</Takeaway>

A golden AMI can be reused more widely. When ShopViet expands to a new Region, **copy the AMI** to that Region. When another team needs it, **share the AMI** with that team's account. An AMI created from encrypted snapshots must also be encrypted when copied; it cannot be copied into an unencrypted copy.

<Takeaway>Shorter launch time: a golden AMI for the fixed part + user data for the changing part. An AMI can be copied to another Region and shared with another account. Keep the RAM state when stopping an instance: Hibernate (part 4).</Takeaway>

Common failures: a hardware fault at 3 a.m., an unresponsive application, temporary data lost after a stop. Simulate each failure, then turn on the matching EC2 feature and run it again:

<Ec2OpsSim client:visible />

<Takeaway>Hardware failure: automatic instance recovery (simplified automatic recovery, on by default for supported instances, or a recover alarm action), which keeps the instance ID and IP addresses. Unresponsive application: reboot alarm action. Instance store is temporary storage and loses data on stop, hibernate or terminate; it suits only buffers, caches and temporary files. Stop an instance and keep the RAM state: Hibernate. Automatically replace a single instance and keep its IP: ASG min = max = 1 + an Elastic IP attached by user data. 1-minute metrics: detailed monitoring.</Takeaway>

</Scene>
