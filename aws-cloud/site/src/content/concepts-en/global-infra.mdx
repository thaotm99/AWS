<Scene id="en-s1" label="Part 1/6" title="Region scope: resources are not automatically available in another Region" questions={["exam1_q41", "exam4_q5"]}>

A **Region** is an independent geographic area, for example Singapore or Tokyo. Many resources, such as **AMIs** and **EBS snapshots**, exist only in the Region where they were created. ShopViet needs to prepare a recovery plan in Tokyo. Perform each step in turn, or try launching directly in Tokyo to see the result.

<AmiCopySim client:visible />

<Takeaway>AMIs and snapshots are Regional resources. To use them in another Region, they must be copied; when you copy an AMI, AWS automatically creates the corresponding snapshot in the destination Region. For fast recovery in another Region, the AMI must be copied to that Region in advance.</Takeaway>

</Scene>

<Scene id="en-s2" label="Part 2/6" title="The scope of each resource type" questions={["exam1_q42", "exam3_q62"]}>

A Region consists of multiple **Availability Zones (AZs)**: data centers with independent power and networking, connected to each other by a private low-latency network. The scope of a resource determines its fault tolerance. Select each ShopViet resource to see its scope.

<ScopeExplorer client:visible />

<Takeaway>Regional resources (S3, EFS, AMI, VPC) can be used from every AZ. AZ-scoped resources (subnet, EC2, EBS, NAT gateway in zonal mode) are tied to one AZ; to tolerate an AZ failure, these resources must be created in multiple AZs. A NAT gateway in regional mode automatically expands to the AZs that have workloads.</Takeaway>

</Scene>

<Scene id="en-s3" label="Part 3/6" title="The impact of an Availability Zone failure" questions={["exam1_q2", "exam2_q8", "exam2_q32"]}>

ShopViet runs 2 EC2 web servers behind a load balancer. Each dot represents a user request. Choose a server placement, then trigger a failure to see the impact.

<AzFailureSim client:visible />

<Takeaway>The standard fault-tolerant architecture: EC2 in an Auto Scaling group spread across at least 2 AZs, behind a load balancer. Two servers in the same AZ both stop working when that AZ fails.</Takeaway>

</Scene>

<Scene id="en-s4" label="Part 4/6" title="Edge locations: CloudFront for downloads, S3 Transfer Acceleration for uploads" questions={["exam1_q62", "exam6_q5", "exam6_q58", "exam1_q18", "exam3_q37"]}>

**Edge locations** are AWS points of presence located close to users, far more numerous than Regions. **CloudFront** caches content at these locations; the origin can be S3, an ALB or an on-premises server. ShopViet's product images are stored in S3 in Singapore. Fetch an image twice to compare the results.

<EdgeCacheDemo client:visible />

In the other direction, when a distant supplier **uploads** large files to S3, the right solution is **S3 Transfer Acceleration**: data enters the edge location close to the upload source, then travels over the AWS network to the bucket; this solution is often combined with **multipart upload**.

<Takeaway>High latency when distant users fetch content: CloudFront (even when the backend must stay where it is). Slow uploads of large files to S3: S3 Transfer Acceleration combined with multipart upload. A requirement in both directions: use both together.</Takeaway>

</Scene>

<Scene id="en-s5" label="Part 5/6" title="Global Accelerator: static IP addresses, TCP/UDP and failover between Regions" questions={["exam1_q59", "exam2_q7", "exam2_q22", "exam3_q8", "exam3_q45", "exam4_q58", "exam5_q4", "exam5_q30", "exam5_q55", "exam1_q62", "exam6_q5", "exam6_q58", "exam1_q18", "exam3_q37"]}>

**AWS Global Accelerator** also uses edge locations but does not cache content. The service provides **2 static anycast IPv4 addresses** (dual-stack: 2 additional IPv6 addresses), receives TCP/UDP traffic at the edge location closest to the user, then carries it over the AWS private network to the nearest healthy endpoint (ALB, NLB, EC2 or Elastic IP) in one or more Regions. The simulation below compares it with a DNS-only approach when a Region fails:

<GlobalAcceleratorSim client:visible />

The three services all use edge locations but solve three different problems. Choose a ShopViet scenario, apply each service in turn and press **Send traffic** to find the service that meets the requirement.

<EdgeChoiceSim client:visible />

<Takeaway>UDP, static IP addresses for partners to put in an allow list, or Region failover that does not depend on DNS: Global Accelerator. Caching pages, images, video: CloudFront. Uploading large files to S3: S3 Transfer Acceleration.</Takeaway>

</Scene>

<Scene id="en-s6" label="Part 6/6" title="Data flows that incur data transfer charges" questions={["exam2_q62", "exam3_q47", "exam5_q2"]}>

When ShopViet's AWS bill grows, the cause is often not the unit price of a service but data flows that were not designed well. Below are three scenarios that commonly incur charges. Choose a scenario and compare the two options.

<CostPatterns client:visible />

<Takeaway>A Read Replica in the same Region has no replication charge; a Read Replica in another Region does. EC2 in a private subnet reading and writing S3 in the same Region: use an S3 gateway endpoint instead of a NAT gateway. Keep large traffic volumes inside AWS and send only the small amount of data out.</Takeaway>

</Scene>

<Scene id="en-confuse" label="Common mistakes" title="Four common configuration mistakes when expanding infrastructure" questions={["exam1_q42", "exam3_q62", "exam6_q58", "exam3_q22"]}>

The four requirements below look simple but are often configured wrongly as ShopViet expands its infrastructure. Choose a scenario, try the option that is commonly applied first, then compare it with the correct option.

<GlobalMythsSim client:visible />

<Takeaway>EFS can be accessed from another Region through inter-Region VPC peering, without copying data. A public NAT gateway in zonal mode is placed in a public subnet (regional mode does not need a public subnet); an egress-only internet gateway is for IPv6 only. To identify the same AZ as another account: use the AZ ID. To accelerate both downloads and uploads: use CloudFront and S3 Transfer Acceleration together.</Takeaway>

</Scene>
