<Scene id="en-s1" label="Part 1/3" title="AWS WAF: filtering malicious requests before they reach the application" questions={["exam5_q13", "exam1_q6", "exam5_q45", "exam2_q30", "exam6_q60", "exam5_q57", "exam2_q32"]}>

<p class="scene-intro">Part of the traffic reaching a website is malicious; a filter placed in front of the application can block those requests before they reach the servers.</p>

Six kinds of requests are being sent to ShopViet, including a legitimate shipping partner calling from abroad with a fixed IP address. Turn on each rule, choose the resource associated with AWS WAF, then send the requests.

AWS WAF evaluates the rules in a web ACL by **priority**, from the lowest numeric setting up, until it finds a matching rule with a terminating action (Allow or Block) or exhausts all rules. So when ShopViet blocks countries with a geo match rule but must still allow some partner IP addresses, it places an IP set rule with those addresses and the Allow action at a lower priority number than the geo match rule: the partner's request is allowed immediately and is never evaluated by the geo match rule.

<WafSim client:visible />

<Takeaway>SQL injection, XSS: managed rule. Restricting by country: geo match. One malicious IP: IP set with the Block action. An exception for partner IP addresses in a blocked country: IP set with the Allow action at a lower priority number than the geo match rule. Requests at an unusual rate: rate-based rule (evaluation window of 1, 2, 5 or 10 minutes, 5 minutes by default; minimum threshold of 10 requests). AWS WAF is associated with CloudFront, ALB, API Gateway REST APIs and some other services (AppSync, Cognito, App Runner, Verified Access, Amplify); it is not attached directly to EC2. AWS WAF inspects only **HTTP and HTTPS** requests; SFTP (SSH) traffic to an AWS Transfer Family endpoint does not pass through AWS WAF, so source IPs for SFTP are restricted with the security group of a VPC hosted endpoint.</Takeaway>

</Scene>

<Scene id="en-s2" label="Part 2/3" title="Six security incidents and the matching services" questions={["exam3_q58", "exam6_q4", "exam1_q36", "exam3_q1", "exam6_q14", "exam2_q44"]}>

<p class="scene-intro">Not every security incident comes from web requests; many happen inside the account, and each kind has a service built to detect or prevent it.</p>

AWS WAF filters only web requests. Many other incidents happen **inside** the account: a compromised server, a sensitive file stored in the wrong place, a new account missing its configuration. Choose an incident, turn the matching service on or off, then simulate the incident.

<IncidentSim client:visible />

<Takeaway>Large-scale DDoS, with support from the AWS team and reports: Shield Advanced. A compromised server mining cryptocurrency: GuardDuty. Software vulnerabilities on EC2: Inspector. Personal data in S3: Macie. Applying consistent rules across many accounts: Firewall Manager. Centralizing security logs: Security Lake.</Takeaway>

</Scene>

<p class="scene-intro">Many security services have similar names or scopes; matching each problem to the right one avoids overlap and needless cost.</p>

Some services are often considered alongside AWS WAF but solve a different problem: aggregating alerts, managing rules across accounts, resolving domain names, or filtering non-HTTP traffic. Select each item to see what it is for and what fits the ShopViet situation.
