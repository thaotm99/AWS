<Scene id="en-s1" label="Part 1/4" title="Alias and CNAME records" questions={["exam2_q2", "exam3_q19", "exam3_q64"]}>

ShopViet needs four records: the main domain pointing to CloudFront, the main domain pointing to www, www pointing to the ALB, and blog pointing to an external WordPress site. Both **Alias** and **CNAME** records map a name to another target, but not every case can be created. Choose each record and record type, then press create to see Route 53's response.

<AliasCnameSim client:visible />

Alias and CNAME are only two of the record types in a hosted zone. Each record type answers a different kind of query: A and AAAA return IP addresses, MX specifies mail servers, NS identifies name servers, and PTR looks up a domain name from an IP address. Choose each ShopViet requirement, then try the record types to find the one that fits and see why the others do not.

<RecordTypeSim client:visible />

<Takeaway>Zone apex: a CNAME cannot be created; point to an AWS resource at the zone apex with an Alias record. Pointing to CloudFront, an ALB or an S3 website: Alias (no charge for Alias queries to AWS resources). A subdomain pointing to another domain name: a CNAME can be used. Name → IPv4: A; IPv6: AAAA. Email: MX (the lower priority value takes precedence). Delegating a subdomain to another hosted zone: NS. IP → name: PTR.</Takeaway>

</Scene>

<Scene id="en-s2" label="Part 2/4" title="TTL: users still reach the old target after a DNS record changes" questions={["exam4_q3"]}>

ShopViet moves to a new load balancer and updates the record in Route 53. Choose a TTL value, then change the record and watch when each client switches to the new target.

<TtlSim client:visible />

<Takeaway>Each DNS response is cached for the duration of the TTL. After the record changes, a client switches to the new target only when its cache expires.</Takeaway>

</Scene>

<Scene id="en-s3" label="Part 3/4" title="Routing policies: a DNS response per user" questions={["exam2_q6", "exam1_q38", "exam4_q61", "exam5_q56", "exam2_q59"]}>

ShopViet runs ALBs in Singapore, Frankfurt and N. Virginia. Choose a routing policy, then simulate access by three users in three regions.

<RoutingPolicySim client:visible />

<Takeaway>Latency: the Region with the lowest latency. Geolocation: by the user's location, used to restrict content by region. Geoproximity: by geographic distance, with bias to adjust the size of a region. Active-passive failover: switches to the standby resource when health checks mark the primary as unhealthy.</Takeaway>

</Scene>

<Scene id="en-s4" label="Part 4/4" title="Hybrid DNS: resolving names between the VPC and the office" questions={["exam1_q63", "exam3_q35", "exam2_q20", "exam6_q63"]}>

Servers in the VPC need to resolve the address of the database at the office (`db.corp.local`), while systems at the office need to call an internal API in the VPC (`api.shopviet.internal`, in a private hosted zone). **Route 53 Resolver** provides two endpoint types for these two directions of resolution.

<HybridDnsSim client:visible />

<Takeaway>The VPC resolves on-premises domain names: outbound endpoint combined with a forwarding rule. On premises resolves domain names in the VPC: inbound endpoint. A private hosted zone requires the VPC to enable both enableDnsHostnames and enableDnsSupport.</Takeaway>

</Scene>

<Scene id="en-confuse" label="Common mistakes" title="Five common DNS configuration mistakes" questions={["exam4_q59", "exam5_q56", "exam1_q38", "exam4_q61", "exam4_q53"]}>

Five situations that come up as ShopViet operates its DNS. Try the option that is usually chosen first, then switch to another option to compare.

<Route53MythsSim client:visible />

<Takeaway>NLB with cross-zone load balancing turned off: each node distributes traffic only to targets in its own AZ, so in an AZ with fewer targets, each target carries more load. Showing an error notice page during a failure: active-passive failover, not weighted. Adjusting the size of a region: geoproximity with bias. Restricting by country: Route 53 geolocation at the DNS layer, CloudFront geo restriction at the content delivery layer. A traffic spike: multivalue answer (up to 8 healthy records, chosen at random) adds no capacity and is not a substitute for a load balancer; add capacity with an [Auto Scaling group](/concepts/asg/#en-s1) behind the ALB.</Takeaway>

</Scene>
