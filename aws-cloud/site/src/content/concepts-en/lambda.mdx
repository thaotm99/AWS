Some problems appear only after deploying to production: a function attached to a VPC cannot reach the internet, users wait a long time at peak hours, notifications are throttled when the concurrency quota is exceeded, the database password is stored in configuration. Pick each scenario, try it, then turn on the option to fix it:

<LambdaRunSim client:visible />

Two more notes. Each invocation of a standard Lambda function runs at most **15 minutes** (900 seconds; Lambda Managed Instances allows up to 90 minutes for asynchronous invocations or through an event source mapping, except Amazon MQ and Amazon DocumentDB); longer jobs should run as containers on Fargate (Containers lesson). When many functions share a library, package that library as **Lambda Layers**.

<Takeaway>Lambda in a VPC needs a NAT gateway to reach the internet. Cold starts at peak hours: provisioned concurrency. Concurrency has a quota per account and Region; configure an alarm on ConcurrentExecutions. Do not store passwords: IAM database authentication. Cross-account access: both the execution role and the bucket policy must allow it.</Takeaway>

</Scene>

The mobile app, sales partners and the admin site all call `api.shopviet.vn`. **API Gateway** runs a series of checks before a request reaches the application code. Pick a scenario and send a request:

<ApiGatewaySim client:visible />

Some other requirements:

- Chat between buyers and sellers needs a two-way connection where the server pushes messages to clients: **WebSocket API**. With a REST API, each request is independent and no connection is kept open.
- Shippers send their location continuously for order tracking: API Gateway receives the data and pushes it into Kinesis Data Streams for **Amazon Managed Service for Apache Flink** (formerly Amazon Kinesis Data Analytics) to analyze the stream.
- Receive transactions from the app, run simple data validation, then process them, with the lowest operational cost: **REST API + Lambda** for validation, with a serverless backend behind it. There are no servers or containers to patch.

<Takeaway>Restrict access to internal IP ranges: resource policy. Token validation without writing code: a REST API with a Cognito user pool authorizer, or an HTTP API with a JWT authorizer (HTTP APIs do not support resource policies, API keys or caching). Limits per client: usage plan + API key. Reduce backend load for repeated requests: caching. Long-running tasks: API Gateway pushes into SQS. Two-way communication: WebSocket API.</Takeaway>

</Scene>
