Every new object on S3 is encrypted. The decision to make is **who manages the key** and **who can track key usage**. Each scenario below is a real ShopViet requirement. Choose a scenario, change the configuration and press Run to watch the object's path and the services that are called.

<S3EncryptSim client:visible />

<Takeaway>Auditing or controlling who can use the key: SSE-KMS. Automatic key rotation: customer managed key + automatic rotation (365 days by default, configurable from 90 to 2560 days). High KMS cost: turn on S3 Bucket Keys and keep SSE-KMS. One key for multiple Regions: multi-Region keys. A key per object with no extra configuration: SSE-S3. The key must be kept outside AWS: SSE-C (since April 2026 blocked by default on new buckets; it must be re-enabled with PutBucketEncryption).</Takeaway>

<Scene id="en-s3" label="Part 3/3" title="Encryption at rest and in transit" questions={["exam2_q40", "exam4_q31", "exam2_q45", "exam5_q40", "exam5_q15", "exam2_q9"]}>

KMS protects data **at rest**. Data **in transit** between machines needs SSL/TLS, and HTTPS requires a valid certificate. A simulation of six situations ShopViet meets in operations:

<DataGuardSim client:visible />

<Takeaway>At rest: KMS. In transit: SSL/TLS. Encryption cannot be turned on directly for a running RDS instance: snapshot → encrypted copy → restore. Certificate for CloudFront: ACM in us-east-1. Imported certificates: ACM does not renew them automatically; track expiration with the AWS Config rule `acm-certificate-expiration-check` (14 days by default, configured through `daysToExpiration`) + SNS, or the EventBridge event "ACM Certificate Approaching Expiration" (from 45 days before by default).</Takeaway>

</Scene>
