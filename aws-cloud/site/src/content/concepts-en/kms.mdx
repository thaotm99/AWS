<Scene id="en-s1" label="Part 1/4" title="Server-side encryption for invoices on Amazon S3" questions={["exam1_q22", "exam2_q50", "exam4_q6", "exam5_q46", "exam5_q11", "exam2_q46", "exam3_q24"]}>

<p class="scene-intro">Encrypted data cannot be read without the key, so the key questions are who holds the key and who may use it.</p>

Every new object on S3 is encrypted. The decision to make is **who manages the key** and **who can track key usage**. Each scenario below is a real MFTech requirement. Choose a scenario, change the configuration and press Run to watch the object's path and the services that are called.

<S3EncryptSim client:visible />

<Takeaway>Auditing or controlling who can use the key: SSE-KMS. Automatic key rotation: customer managed key + automatic rotation (365 days by default, configurable from 90 to 2560 days). High KMS cost: turn on S3 Bucket Keys and keep SSE-KMS. One key for multiple Regions: multi-Region keys, chosen when the key is created (a single-Region key cannot be converted; existing data must be copied to re-encrypt it under the new key). A key per object with no extra configuration: SSE-S3. The key must be kept outside AWS: SSE-C (since April 2026 blocked by default on new buckets; it must be re-enabled with PutBucketEncryption).</Takeaway>

</Scene>

<Scene id="en-s3" label="Part 3/4" title="Encryption at rest and in transit" questions={["exam2_q40", "exam4_q31", "exam2_q45", "exam5_q40", "exam5_q15", "exam2_q9"]}>

<p class="scene-intro">Data needs protection in two states: at rest (stored) and in transit (moving over the network); each state uses a different encryption mechanism.</p>

KMS protects data **at rest**. Data **in transit** between clients, applications and databases needs SSL/TLS, and HTTPS requires a valid SSL/TLS certificate. A simulation of six situations MFTech meets in operations:

<DataGuardSim client:visible />

<Takeaway>At rest: KMS. In transit: SSL/TLS. Encryption cannot be turned on directly for an existing unencrypted RDS DB instance: DB snapshot → encrypted snapshot copy → restore. Certificate for CloudFront: an ACM certificate in us-east-1. Imported certificates: ACM does not renew them automatically; track expiration with the AWS Config rule `acm-certificate-expiration-check` (14 days by default, configured through `daysToExpiration`) + SNS, or the EventBridge event "ACM Certificate Approaching Expiration" (from 45 days before by default).</Takeaway>

</Scene>

<Takeaway>Encryption context: authenticated data bound to the ciphertext, not a key generator. Imported key material and CloudHSM: more control, but no automatic rotation. Client-side encryption: the application encrypts before sending and does not use S3 Bucket Keys. Multi-Region: chosen at key creation, never converted later.</Takeaway>
