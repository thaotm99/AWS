**Application Load Balancer** (ALB) đọc được request HTTP: đường dẫn, tên miền, header. **Network Load Balancer** (NLB) chỉ chuyển tiếp kết nối TCP/UDP, nhưng có IP tĩnh và rất nhanh. Thử từng việc ShopViet cần làm, lần lượt với ALB và NLB:

<LbTypeSim client:visible />

ShopViet sắp mở thêm Region ở Mỹ. Một load balancer có chia được cho cả hai Region không?

<Takeaway>Web cần chia theo URL, tên miền: ALB. TCP/UDP thuần, IP cố định cho đối tác, PrivateLink: NLB. Server để ở private subnet, chỉ load balancer ở public subnet. Mỗi load balancer chỉ phục vụ trong một Region.</Takeaway>

</Scene>

<Scene id="s2" label="Cảnh 2/4" title="Mỗi server nhận bao nhiêu phần trăm traffic?" questions={["exam3_q14", "exam4_q59"]}>

Đợt khuyến mãi, ShopViet thêm gấp server ở AZ B nhưng AZ A vẫn chỉ có 1 server. Server lẻ đó có bị quá tải không? Kéo thanh trượt và bật/tắt cross-zone. Thử 1 server ở AZ A, 4 server ở AZ B; rồi 4 và 6.

<CrossZoneCalc client:visible />

<Takeaway>DNS chia đều cho node của load balancer ở từng AZ. Cross-zone bật: chia đều cho mọi target. Cross-zone tắt: mỗi AZ nhận một phần bằng nhau rồi chia cho target trong AZ đó, nên AZ ít server sẽ bị dồn tải.</Takeaway>

</Scene>

<Scene id="s3" label="Cảnh 3/4" title="Một ALB, nhiều service và nhiều tên miền" questions={["exam1_q48", "exam4_q40", "exam4_q57", "exam2_q17", "exam1_q6"]}>

ShopViet tách hệ thống thành service đơn hàng, service sản phẩm và các microsite khuyến mãi, mỗi thứ một target group. Tất cả vẫn đứng sau **một** ALB. Mỗi request đi qua listener HTTPS theo thứ tự: chọn chứng chỉ, AWS WAF, đăng nhập, rồi listener rule chọn target group. Chọn tình huống và gửi request:

<AlbRuleSim client:visible />

<Takeaway>Listener rule chia theo path (`/orders/*`) và host (`*.shopviet.vn`; dấu `*` không khớp tên gốc). Nhiều tên miền HTTPS trên một listener: thêm nhiều chứng chỉ, ALB chọn bằng SNI. ALB tự lo đăng nhập với Cognito và gắn được AWS WAF.</Takeaway>

</Scene>

<Scene id="s4" label="Cảnh 4/4" title="Server khỏe mà vẫn unhealthy?" questions={["exam4_q26", "exam5_q1", "exam2_q18", "exam3_q13"]}>

Một buổi sáng, ALB báo i-2 unhealthy dù kỹ sư SSH vào thấy app vẫn chạy. Load balancer chỉ tin vào **health check**: nó gọi một đường dẫn trên từng server theo chu kỳ. Xem health check đi đâu và bị chặn ở đâu:

<HealthCheckSim client:visible />

<Takeaway>Unhealthy mà app vẫn chạy: kiểm tra security group có cho load balancer vào không, và health check path có đúng không. Muốn ASG thay server mà load balancer báo hỏng: đổi health check của ASG sang ELB.</Takeaway>

</Scene>
