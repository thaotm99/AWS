<Takeaway>Multi-AZ: sao chép đồng bộ, một standby không phục vụ đọc, nhằm đảm bảo khả năng chịu lỗi; failover bằng cách cập nhật CNAME. <Scene id="s2" label="Phần 2/4" title="Năm sự cố vận hành của database đơn hàng" questions={["exam2_q13", "exam6_q19", "exam6_q46", "exam4_q19", "exam1_q3", "exam1_q55", "exam2_q63", "exam4_q47", "exam5_q42", "exam2_q62"]}>

Khi quy mô ShopViet tăng, database phát sinh nhiều vấn đề hơn: báo cáo làm chậm website, Lambda mở quá nhiều kết nối, ổ đĩa đầy, sự cố cấp Region. Chọn từng sự cố, chạy để quan sát hậu quả, sau đó bật tính năng RDS tương ứng và chạy lại:

<RdsOpsSim client:visible />

Hai biện pháp bổ sung giúp giảm tải cho đội vận hành. Hệ thống kế toán chạy SQL Server sử dụng **RDS for SQL Server Multi-AZ**: AWS quản lý standby và failover. Để mọi database mới tuân thủ cùng tiêu chuẩn (Multi-AZ, backup, mã hoá), các database được tạo từ cùng một **CloudFormation template** đã được kiểm định.

<Takeaway>Báo cáo làm chậm website: Read Replica cùng Region (không tính phí replication). Quá nhiều kết nối: RDS Proxy. Nguy cơ đầy ổ đĩa: storage auto scaling. Sự cố cấp Region: cross-Region Read Replica + copy backup sang Region khác. Cần truy cập OS: RDS Custom.</Takeaway>

</Scene>

<AuroraSim client:visible />

<Takeaway>Aurora Replica + reader endpoint phục vụ tải đọc lớn, đồng thời là đích failover. Tải đọc biến động: Aurora Auto Scaling. Nhiều Region, RPO vài giây, RTO khoảng một phút: Global Database. Tải không dự đoán được: Serverless v2.</Takeaway>
