Nếu nhiều account AWS (ví dụ account của từng shop con) cần mount chung một thư mục, EFS vẫn làm được: thêm file system policy cho account kia và mount qua VPC peering hoặc VPC dùng chung.

<Takeaway>Block (EBS): ổ riêng của một instance trong một AZ, tính tiền theo dung lượng cấp phát. File (EFS, FSx): nhiều instance dùng chung. Object (S3): bền nhất, rẻ nhất, truy cập qua API. Lưu cùng một file: S3 Standard rẻ nhất, rồi tới EFS, đắt nhất là EBS.</Takeaway>

<Takeaway>EFS: thư mục NFS dùng chung giữa nhiều AZ. Rất nhiều client: Max I/O. Dữ liệu nhỏ nhưng cần throughput cao: provisioned throughput. File ít dùng: lớp IA. Mount target cùng AZ cho độ trễ thấp.</Takeaway>

<Scene id="s4" label="Cảnh 4/4" title="Bốn nhóm, bốn loại file system" questions={["exam2_q12", "exam2_q56", "exam1_q65", "exam3_q5", "exam3_q43", "exam3_q56", "exam1_q24", "exam3_q61", "exam3_q26"]}>

Ngoài EFS, AWS có ba loại **FSx** cho những nhu cầu chuyên biệt. Bốn nhóm ở ShopViet mỗi nhóm có ba yêu cầu bắt buộc. Thử mount từng file system cho từng nhóm để xem cái nào đáp ứng đủ:

<FsxSim client:visible />

Nếu văn phòng muốn giữ file share SMB tại chỗ nhưng lưu dữ liệu trên S3, dùng **S3 File Gateway** (xem bài Storage Gateway).

<Takeaway>Windows, SMB, NTFS, Active Directory, DFS: FSx for Windows File Server. HPC, đọc song song, nạp từ S3: FSx for Lustre. Đang dùng NetApp, cần NFS + SMB + iSCSI: FSx for NetApp ONTAP. Thư mục chung đơn giản cho Linux: EFS.</Takeaway>

</Scene>
