## asg

Checked 2026-10-22 against the pages below (keyword → claim → URL).

- Step scaling policy → step adjustments sized by the alarm breach; policy keeps responding to alarms while an activity is in progress; instances warming up count toward desired capacity, so breaches in the same step add nothing; designer creates and manages the CloudWatch alarms → https://docs.aws.amazon.com/autoscaling/ec2/userguide/as-scaling-simple-step.html
- Target tracking recommended over step/simple for metrics proportional to capacity; Auto Scaling creates/manages the alarms → https://docs.aws.amazon.com/autoscaling/ec2/userguide/as-scaling-simple-step.html , https://docs.aws.amazon.com/autoscaling/ec2/userguide/as-scaling-target-tracking.html
- Simple scaling policy → single adjustment; must wait for the in-progress scaling activity or health check replacement and the cooldown before responding to additional alarms; AWS recommends target tracking or step instead → https://docs.aws.amazon.com/autoscaling/ec2/userguide/simple-scaling-policies.html
- Cooldown → default 300 seconds; applies to simple scaling; target tracking and step scaling do not wait for it; AWS recommends not using simple scaling and cooldowns → https://docs.aws.amazon.com/autoscaling/ec2/userguide/ec2-auto-scaling-scaling-cooldowns.html
- Instance warmup → instance not counted in aggregated metrics until warmup ends; default instance warmup strongly recommended, not enabled by default → https://docs.aws.amazon.com/autoscaling/ec2/userguide/ec2-auto-scaling-default-instance-warmup.html
- Desired vs min/max → desired must be ≥ min and ≤ max; policies cannot move desired outside the limits; scheduled action without new min/max uses the current limits; a scheduled action sets desired, min and max → https://docs.aws.amazon.com/autoscaling/ec2/userguide/asg-capacity-limits.html , https://docs.aws.amazon.com/autoscaling/ec2/userguide/ec2-auto-scaling-scheduled-scaling.html
- ASG cannot span Regions → "EC2 Auto Scaling groups are regional constructs. They can span Availability Zones, but not AWS regions." → https://aws.amazon.com/ec2/autoscaling/faqs/
- Launch template → AMI, instance type, key pair, security groups; versioned; launch configurations cannot launch both Spot and On-Demand or multiple instance types → https://docs.aws.amazon.com/autoscaling/ec2/userguide/launch-templates.html ; launch configuration cannot be modified after creation → https://aws.amazon.com/ec2/autoscaling/faqs/
- Mixed instances policy → On-Demand base launched before Spot; above-base percentage, rounded up in favor of On-Demand; multiple purchase options only with a launch template; RIs / Savings Plans discount On-Demand in the group; Spot suits stateless web servers → https://docs.aws.amazon.com/autoscaling/ec2/userguide/mixed-instances-groups-set-up-overview.html , https://docs.aws.amazon.com/autoscaling/ec2/userguide/ec2-auto-scaling-mixed-instances-groups.html , https://docs.aws.amazon.com/autoscaling/ec2/userguide/auto-scaling-groups.html
- Spot reclaimed when capacity not available; ASG launches a replacement → https://docs.aws.amazon.com/autoscaling/ec2/userguide/auto-scaling-groups.html
- Scale-in protection → protected instances skipped by scale in (default termination policy evaluates AZs with an unprotected instance); group setting inherited by new instances; does not protect from health check replacement, Spot interruption, manual termination → https://docs.aws.amazon.com/autoscaling/ec2/userguide/ec2-auto-scaling-instance-protection.html , https://docs.aws.amazon.com/autoscaling/ec2/userguide/ec2-auto-scaling-termination-policies.html
- EC2 Impaired status → Auto Scaling waits a few minutes before marking Unhealthy; insufficient-data is not Unhealthy; instance not running is replaced immediately → https://docs.aws.amazon.com/autoscaling/ec2/userguide/health-checks-overview.html
- ELB health check → ignored by default; once turned on, ASG marks the instance Unhealthy on its next periodic check; waits for deregistration delay → https://docs.aws.amazon.com/autoscaling/ec2/userguide/health-checks-overview.html
- Custom health check (SetInstanceHealth) → set-instance-health Unhealthy makes ASG replace the instance; respects the grace period by default, `--no-should-respect-grace-period` overrides; activity cause "in response to a user health-check" → https://docs.aws.amazon.com/autoscaling/ec2/userguide/set-up-a-custom-health-check.html , https://docs.aws.amazon.com/autoscaling/ec2/userguide/replace-unhealthy-instance.html
- Unhealthy replacement order → by default terminate first, then another activity launches while terminating; instance maintenance policy can launch first → https://docs.aws.amazon.com/autoscaling/ec2/userguide/replace-unhealthy-instance.html , https://docs.aws.amazon.com/autoscaling/ec2/userguide/ec2-auto-scaling-instance-maintenance-policy.html
- AZ rebalancing → triggered by explicit terminate/detach; launches new instances before terminating; may exceed max by 10% or 1 instance, whichever is greater → https://docs.aws.amazon.com/autoscaling/ec2/userguide/auto-scaling-benefits.html
