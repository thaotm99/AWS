# FACTCHECK-R4: câu cần đối chiếu với AWS documentation

Lượt R4 (văn phong) chỉ đổi cách diễn đạt, không đổi nội dung kỹ thuật. Các câu dưới đây giữ nguyên ý nhưng có điểm nghi ngờ, cần kiểm tra lại với tài liệu AWS trong lượt fact-check riêng.

| Bài | Câu (bản hiện tại) | Lý do nghi ngờ |
| --- | --- | --- |
| messaging (Phần 4, danh sách) | "Báo cáo kiểm toán chạy bằng Step Functions và đọc dữ liệu hai lần mỗi năm: do state machine đã có cơ chế retry, lưu dữ liệu ở **S3 Standard-IA** là đủ" | Lập luận "vì có retry nên Standard-IA là đủ" không rõ ràng: lý do chọn Standard-IA thường là tần suất truy cập thấp; retry chỉ liên quan tới tính sẵn sàng thấp hơn (99.9%) của Standard-IA. Với dữ liệu đọc 2 lần/năm, Glacier Instant Retrieval có thể rẻ hơn. |
| messaging (MessageLifeSim) | "Short polling chỉ truy vấn một tập con các server của SQS, do đó có thể trả về rỗng ngay cả khi queue có message." | Đúng với tài liệu cũ; cần xác nhận cách diễn đạt hiện hành của SQS docs. |
| messaging (EventRouterSim, AWS Config + SNS) | "Managed rule phát hiện chứng chỉ còn hiệu lực dưới 30 ngày (tham số `daysToExpiration` = 30)" | Giá trị mặc định của `daysToExpiration` trong rule `acm-certificate-expiration-check` là 14; mô phỏng giả định đã cấu hình 30. Cần ghi rõ đây là giá trị tuỳ chỉnh hoặc kiểm tra lại. (Cùng giả định trong monitoring/GuardrailSim.) |
| kinesis (Phần 3, Takeaway, Quiz, StreamPipelineSim) | "Phân tích stream bằng SQL: Kinesis Data Analytics (Managed Service for Apache Flink)" | Kinesis Data Analytics for SQL Applications đã ngừng hỗ trợ; Managed Service for Apache Flink dùng Flink SQL / Studio notebook. Cần xác nhận cách gọi tên và khả năng "SQL" hiện tại. |
| kinesis (ShardThroughputSim) | "On-demand capacity mode: stream tự động tăng capacity ghi theo lưu lượng (tức thời tới gấp đôi mức đỉnh gần nhất)" | AWS mô tả on-demand đáp ứng tới gấp đôi đỉnh của 30 ngày trước; vượt quá có thể bị throttle. Cần kiểm tra mốc "30 ngày" và giới hạn mặc định ban đầu (4 MB/s). |
| kinesis (Takeaway Phần 3) | "Chuyển dữ liệu từ S3 vào stream: AWS DMS" | DMS hỗ trợ S3 làm source và Kinesis Data Streams làm target; cần xác nhận khả năng CDC từ S3 (yêu cầu file CDC theo định dạng DMS), vì StreamPipelineSim nói "chuyển cả dữ liệu hiện có lẫn thay đổi mới". |
| monitoring (Phần 2, Takeaway) / AlarmActionSim | "Alarm scale in: ASG giảm instance tại AZ có nhiều instance nhất, sau đó chọn instance có launch template cũ nhất." | Default termination policy hiện nay còn xét allocation strategy (On-Demand/Spot) trước launch template cũ; câu đang rút gọn. |
| monitoring / backup-dr (recover) | "Recover giữ nguyên instance ID, private IP, Elastic IP, public IPv4 và metadata" | Cần xác nhận việc giữ public IPv4 (tài liệu simplified automatic recovery có nêu), và phân biệt alarm-based recovery với simplified automatic recovery (mặc định bật). |
| iac (Quiz, StackSim) | "gp2 hỗ trợ burst cho các thời điểm I/O cao và có chi phí thấp hơn io1 đáng kể" | Đúng về nguyên tắc; AWS hiện khuyến nghị gp3 thay cho gp2. Không đổi nội dung, chỉ ghi nhận. |
| iac (StackSim) | "Bản thân CloudFormation không tính phí" | CloudFormation tính phí cho handler operations của resource provider bên thứ ba / private registry; với tài nguyên AWS::* thì không tính phí. |
| backup-dr (Phần 2) | "Region phụ được promote thành Region chính trong khoảng một phút" (Aurora Global Database) | Tài liệu AWS nêu RTO thường dưới 1 phút cho managed failover/switchover tuỳ trường hợp; cần xác nhận con số và loại thao tác (managed failover vs detach-and-promote). |
| others (Phần 1, CostWatchSim) | "Khi chi phí chạm 80% ngân sách, Budgets action tự động gắn IAM policy DenyAll ... và stop các EC2 đang chạy" | Một budget action chỉ thực hiện một loại hành động (IAM policy, SCP, hoặc nhắm EC2/RDS); mô phỏng mô tả hai hành động trong một action. Có thể cần hai action. |
